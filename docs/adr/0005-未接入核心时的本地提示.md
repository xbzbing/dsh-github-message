# ADR-0005：未接入核心时独立轮询，用右下角提示代替上报

## 背景

插件最初的用途只有一个：给 `dsh-my-superagent` 提供 GitHub 消息来源。没有核心时它甚至不轮询，
面板只能看到「未接入」。但采集能力（三路只读查询、去重、ETag、限流遵守）本身是独立的，
用户希望在没装核心时也能被提醒到，而不是必须先把核心跑起来。

同时有两条硬约束不能破：

1. 只推送信号，不评审、不写回。
2. `seen` 只在核心真正接受后才写，否则核心升级/开启来源后会漏报。

## 决策

- **轮询与上报解耦**：`runtime.start()` 无条件开始轮询；`attach(service)` 只负责注册来源。
  核心服务消失时 `detachSource()` 撤销注册但继续轮询，插件卸载才 `detach()`。
- **三种状态**：`standalone`（无服务）、`dry-run`（有服务但缺 `github-source`）、`running`（正常上报）。
  前两种都算「未接入」，走本地提示；`running` 完全静默。
- **本地提示是旁路**：`pollOnce` 在 `dryRun || handle === undefined` 时调用
  `onUndelivered(draft)`；提示失败只吞掉，不影响采集与统计。
- **独立台账**：提示过的键写 `notified.json`，**不写 `seen`**。这样同一事实不会每轮重复弹窗，
  接入核心后仍会重新上报，由核心决定要不要打扰主人。
- **客户端拉取而不是服务端推送**：`shell.overlay` 上的浮层每 5 秒调一次 RPC `notices`
  （已接入时降到 30 秒）。首次调用只取游标，不重放历史；刷新页面不会补弹旧消息。
- **首轮宽限 3 秒**：插件加载时如果还没看到 `mySuperagent`，首轮延后 3 秒，
  等同批加载的核心插件先注册，避免「其实已接入却先弹了一条」。

## 代价

- 没接核心时仍然消耗 GitHub API 配额（与 dry-run 相同）。
- 提示只在浏览器页面打开时可见；页面关闭期间的提醒不会补发，也没有系统级通知。
- 提示记录与去重记录是两份文件，`seenTtlMs` 同时约束两者；极端情况下（核心在提示后、上报前接入）
  同一事实会被提示一次、再被核心通知一次。
- `shell.overlay` 依赖 layout 插件提供的框架级槽位；没有该槽位时提示不显示，采集与面板不受影响。
