# ADR-0002：三类信号共用事件键与展示字段

review、issue、mention 三类事实各自映射为一个 `my-superagent/v1` signal，使用稳定的 `subject` 与 `sourceEventId`，让核心可以回源、去重和路由。

## 背景

核心按 `(source, sourceEventId)` 幂等吸收信号，并通过 `subject` 找到回源对象。GitHub 没有统一的「待办 ID」：PR 要按 head 提交去重，Issue 按编号，@ 提醒按评论。若每条事实都用轮询时间当键，会在每轮产生新记录。

## 决策

| kind | subject | sourceEventId |
| --- | --- | --- |
| `code-review.requested` | `github:<owner>/<repo>/pull/<n>` | `review:<repo>#<n>:<headSha>` |
| `github.issue.opened` | `github:<owner>/<repo>/issues/<n>` | `issue:<repo>#<n>` |
| `github.mention` | `github:<owner>/<repo>/issues/<n>` | `mention:<repo>#<n>:<commentId|body>` |

- PR 推新 commit（head SHA 变化）才算新事实；只改标题/描述不重复提醒。
- Issue 只在创建时提醒一次；后续编辑与评论不重复。
- 评论级 @ 按 comment id 去重；没有评论 id 时用固定的 `body` 标记兜底，避免正文编辑产生新事件。
- `repo` 在事件键中小写归一化，展示保留 GitHub 返回的大小写。
- 所有外部文本去控制字符、压成单行并按字段截断；链接只接受 `https://github.com/...`。

## 代价

- 同一 PR 的多次评审请求（例如被重新请求）不会再次提醒，除非 head 变化。
- 没有评论 id 时同一 Issue/PR 正文只提醒一次；正文后续再编辑不会重复提醒。
- 核心需要理解 `github:` subject 的路径格式，解析逻辑由 issue #1 定义。
