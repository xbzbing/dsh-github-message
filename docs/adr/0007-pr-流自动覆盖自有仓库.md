# ADR-0007：PR 流自动覆盖自有仓库

PR 流新增 `prScope: 'review' | 'owned'`，默认 `review` 保持原行为；`owned` 额外用 `user:@me`、`org:<name>` 与显式 `repos` 覆盖我名下仓库里别人开的 PR，并以新 kind `github.pr.repo` 上报给核心，由核心的 `review.repoPr` 决定要不要评审。

## 背景

原来的 PR 流只查 `review-requested:@me`：只有被显式请求评审（人或团队）的 PR 才会提醒。个人小项目里常见的形态是别人直接在我的仓库开 PR，既没有指定评审人，也不会 @ 我，于是这类 PR 完全收不到通知。Issue 流已用 `issueScope: owned` 覆盖了同类问题（[ADR-0006](0006-issue-流自动覆盖自有仓库.md)），PR 侧需要对称的能力。

GitHub search 支持 `is:pr is:open user:USERNAME`（仓库 owner 限定）与 `org:ORGNAME`，可以一条查询覆盖一类来源，不必逐个仓库轮询。

## 决策

- 增加 `prScope`，默认 `review`；`owned` 时来源为 `user:@me` + 每个 `orgs` 条目 + 原有 `repos` 列表，与 issue 流共用 `orgs` 与 `maxOrgs`。
- 查询语句统一由 `ownedPullSources` 生成（`OWNED_PULL_QUERY` / `orgPullQuery` / `repoPullQuery`）；非法组织名或仓库名计入 `skipped`，不拼进搜索语句。
- 候选复用 review 流的取数管线（含 PR 详情、head SHA、draft 与时间窗过滤）；随后过滤掉作者是主人自己的 PR——那类由自提 PR 流负责，避免同一 PR 被两条流重复上报。
- 跨来源按 `repo#number` 去重，合并后按 `updatedAt` 倒序截断到 `maxResults`，单个来源不能占满全局预算。
- 新增独立 kind `github.pr.repo`，事件键前缀用 `repo:`（自提 PR 是 `self:`），`payload.via` 为 `repo-owned`。不复用 `github.pr.opened`：核心对该 kind 会先按 `review.selfPr` 提前结算，且评审关系闸按 kind 放行作者关系，复用会让「别人开的 PR」被自提开关与关系闸误判。旧核心对未知 kind 记 `ignored/unverified-external`，不会误触发。
- 统计上单独一条 `repoPr` 流，与 `selfPr` 并列，便于判断 owned 覆盖是否真的生效。
- 面板在「维护仓库」卡片里增加「自动覆盖我名下仓库的新 PR」开关；组织列表在任一 owned 模式下显示，保存时一并写入运行时 `config.json`。

## 代价

- `owned` 模式每轮多 1 次 `user:@me` 查询，加上每个组织与每个显式仓库各 1 次；PR 详情还要一次 `pulls/{n}`。默认 5 分钟一轮，仓库/组织多时请求数线性增长。
- 只覆盖 open PR，不覆盖已合并/已关闭的历史；也不覆盖评论、review、push 等事件。
- 插件只上报事实，**是否会真的评审由核心的 `review.repoPr` 决定**。核心未实现该开关时，`github.pr.opened` 的作者不是主人会被判 `unrelated`，等于不提醒——需要核心侧提案落地（见 `docs/proposal/`）。
- 组织查询不校验当前账号是否属于该组织；填错只会得到空结果，不会越权读取。候选仍由核心回源校验仓库写权限。
