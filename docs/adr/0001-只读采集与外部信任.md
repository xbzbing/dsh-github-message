# ADR-0001：只读采集、外部信任，核心未支持时只采集不推送

`dsh-github-message` 只负责把 GitHub 事实翻译成信号；评审、Issue 分析、评论写回与是否打扰主人全部由 `dsh-my-superagent` 决定。插件以 `trust: 'external'` 注册，核心回源确认后才采纳。

## 背景

GitHub 的评审与 Issue 分析需要 DSH 会话、权限与写回策略，放在来源插件里会把采集和决策耦合在一起，也难以复用核心的注意力调度与去重。主人明确要求「自动评审和写回由 superagent 完成，github-message 只负责消息推送」。

核心当前只对 `icode:` subject 做回源；`github:` subject 的验真与路由由 [issue #1](https://github.com/xbzbing/dsh-my-superagent/issues/1) 实现。插件先落地时，如果直接 emit，核心会把信号记为 `ignored`，而插件又写了 `seen`，等核心升级后反而漏报。

## 决策

- 插件只调用 `gh api` 的 GET/search/notifications，不包含任何写接口。
- 注册时固定 `trust: 'external'`，不冒充 `system`。
- 注册时读取 `mySuperagent.protocol.features`；缺少 `github-source` 时进入 dryRun：
  照常采集、统计与展示候选，但不 emit、不写 `seen`。
- 来源默认关闭；`emit` 返回 `source-disabled` 时不写 `seen`，下一轮重试。
- 子进程使用最小环境，不传 `GH_TOKEN` / `GITHUB_TOKEN`，由 `gh` 自己读 keyring。

## 代价

- 核心支持前，插件面板只能显示候选数量，不能产生真实提醒。
- dryRun 期间每轮仍会消耗 GitHub API 配额；面板会明确标注。
- 依赖本机 `gh` 登录；未安装或未登录时功能不可用。
