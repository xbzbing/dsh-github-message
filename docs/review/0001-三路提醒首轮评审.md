# 评审 0001：三路提醒首轮实现

- 日期：2026-11-08
- 范围：`src/`、`src/client/`、`test/`、`scripts/` 与相关文档
- 方式：隔离上下文的子代理按 correctness / readability / architecture / security / performance 五轴评审；作者逐条修复并补回归测试。

## 结论

首轮实现的核心边界成立：只读 GitHub、只上报信号、`trust: 'external'`、来源关闭与 dry-run 都不写 `seen`。
评审发现的正确性、边界校验与性能问题已修复；剩余项是明确接受的取舍，不阻塞交付。

## 已修复

| 轴 | 发现 | 处理 |
| --- | --- | --- |
| correctness | mention 游标/ETag 会被其他流的错误阻止推进，导致每轮重扫 | `mentionSettled` 只看 mention 流自身是否完成、是否认证、是否有错 |
| correctness | 401 后自动轮询永久停在 `expired`，终端重新登录也不会恢复 | `login.api !== 'ok'` 时自动重新 `probeLogin`，补恢复用例 |
| correctness | detach 后仍在途的轮询可能继续 emit、写统计与 seen | 传入 `isActive`，流与候选之间检查；轮询返回后再检查一次生命周期 |
| correctness | issue 流第一个仓库可能占满全局 `maxResults` | 每仓库先取候选，再全局按 `createdAt` 归并截断 |
| correctness | 无 `commentId` 的 mention 用时间戳做事件键，正文编辑会重复提醒 | 固定用 `body` 兜底，同一 Issue/PR 正文只提醒一次 |
| correctness | search 降级只读评论第一页，深线程里的 @ 会漏 | 最多翻 5 页（500 条），保留最新一条命中 |
| security | `githubUrl` 接受带 userinfo 或显式端口的地址 | 拒绝 `https://u:p@github.com/...` 与 `:8443` |
| security | `apiPathFromUrl` 接受任意 `repos/...` 路径 | 只接受 `repos/<o>/<r>/(issues|pulls)/comments/<id>` |
| robustness | `gh` 输出超过 8MB 时静默截断，可能把半截 JSON 当合法响应 | 以 `invalid-output` 拒绝，不再静默降级 |
| performance | 面板每次 `status()` 都同步打开核心 SQLite | 核心信号统计缓存 5 秒，面板刷新周期 10 秒 |
| correctness | 单条候选翻译异常会中断整条流 | 每个候选独立 try/catch，记错后继续 |
| correctness | `gh` 对 304 仍以非零退出，条件请求被记成错误且 ETag 无法复用 | stdout 是完整 304 响应时按条件响应返回；补 runner 用例 |
| correctness | 限流 403 被归为 forbidden | 限流判断提前，并覆盖 429 |

## 接受的取舍

- **不取消已发出的 `gh` 子进程**：detach 只在请求/候选之间停止；最多等当前只读请求结束，不产生写操作。
- **search 降级最多翻 5 页评论**：更深的 @ 可能漏；notifications 是主路径，search 只是缺少 scope 时的兜底，优先控制 30 次/分钟的搜索限额。
- **issue 归并的内存上限**：每个仓库最多取 `maxResults`，仓库上限 10，最坏 1000 条候选后再排序；有界，可接受。
- **正文 mention 只提醒一次**：没有评论 id 时无法区分「同一条评论编辑」与「新评论」，选择不重复打扰。
- **search 不做条件请求**：GitHub search 的 ETag 行为不稳定，改为按窗口与 `seen` 去重，避免无效请求。
- **PR 详情缓存只在单轮内**：跨轮重新取详情，换取实现简单与状态新鲜；轮询周期 5 分钟，请求量可控。
- **核心准入仍会忽略信号**：`github:` subject 与 `github-source` feature 由核心 issue #1 实现；插件侧不做绕过。
- **不包含任何 GitHub 写操作**：评审、Issue 分析、评论与合入都由 `dsh-my-superagent` 完成。
