# 核心提案：仓库自有 PR 的评审（`review.repoPr`）

> 2026-11-09 状态：待核心实现。插件侧 `prScope: owned` 已就绪（[ADR-0007](../adr/0007-pr-流自动覆盖自有仓库.md)），
> 新增 kind `github.pr.repo`；核心未实现前，这个 kind 会被判 `ignored/unverified-external`。

## 背景

`dsh-github-message` 的 PR 流现在有两条：

- `code-review.requested`：`review-requested:@me`，别人（或团队）请求我评审。
- `github.pr.opened`：`author:@me`，我自己提的 PR，由核心的 `review.selfPr` 决定要不要评审（ADR-0087）。

两条都不覆盖最常见的个人项目形态：**别人直接在我的仓库开 PR，没有指定评审人，也没有 @ 我**。插件新增 `prScope: owned`
后会用 `user:@me` / `org:<name>` / `repo:<owner>/<repo>` 搜索这类 PR，并以**新 kind `github.pr.repo`** 上报
（事件键 `repo:<repo>#<n>:<headSha>`，`payload.via = 'repo-owned'`）。

不复用 `github.pr.opened`，是因为核心侧两条现有逻辑会误判：

1. `confirmGithub` 对 `github.pr.opened` 会**先**按 `review.selfPr` 提前结算（`ignored/self-pr-disabled`），
   不管作者是谁。复用时「别人在我仓库开的 PR」会被自提开关错误地把关。
2. 评审关系闸的 `selfReviewSignal()` 只按 kind 判断，不区分作者；复用时会把这类 PR 当成自提 PR 放行 `author` 关系，
   属于权限语义混淆。

独立 kind 让两条闸互不干扰，旧核心对未知 kind 记 `ignored/unverified-external`，不会误触发。

## 目标

核心新增默认关闭的开关 `review.repoPr`，让「我（或我的组织）名下仓库里别人开的 open PR」进入评审提醒与评审任务，
复用现有回源、通知判重、并发控制与审计。

## 非目标

- 不合入、不推送、不改他人 PR；写回仍受来源权限档位与既有白名单约束。
- 不覆盖 Issue、评论、review、push 等其它事件。
- 不做仓库自动发现（范围仍由插件按 `user:@me` / `orgs` / `repos` 决定）。
- 不改变 `review.selfPr` 与 `github.pr.opened` 的语义。

## 设计

### 1. 信号形状

`src/host/sources/github.ts`：

```ts
export const GITHUB_KIND_SHAPE = Object.freeze({
  'code-review.requested': 'pull',
  'github.pr.opened': 'pull', // 自提 PR（ADR-0087）
  'github.pr.repo': 'pull',   // 我名下仓库里别人开的 PR（本提案）
  'github.issue.opened': 'issues',
  'github.mention': 'issues',
} as const);
```

subject 仍是 `github:<owner>/<repo>/pull/<n>`，形状校验无需改动。
`payload.author` 与 `payload.headSha` 已由插件提供，可用来做作者判断与判重。

### 2. 设置

`SettingsSchema.review` 增加：

```ts
// 我名下仓库里别人开的 PR 也进入评审：默认关，误报会打扰主人。
repoPr: s.optional(s.boolean()),
```

默认值 `repoPr: false`（`defaultSettings()` 与 `Settings` 类型同步）。设置页「评审任务」增加开关，文案建议
**「我仓库里别人开的 PR 也评审」**，说明「开启后，作者不是你、也没有请求你评审的 open PR 会出现在提醒里；
仍需 `review.auto` 或点卡片才会真正开始评审」。

### 3. 回源（`src/host/sources/github.ts` + `verification.ts`）

新增 `verifyRepoPull`（或给 `verifyPull` 加分支）：

- PR 必须 `state === 'open'` 且未合入；`head.sha` 必须是 40 位十六进制，否则 `mismatch`。
- 作者必须**不是**主人（`loginOf(pull.user) !== login`）；是自己则交回 `github.pr.opened` 处理。
- 主人在该仓库必须有 `admin` / `maintain` / `push` 权限（复用 `verifyIssue` 里 `gh-repo` + `permissions` 的判断）。
- 通过后给评审提醒，判重键与「待我评审」相同：`ps:<sha>`，保证同一 PR 从两条流进来只提醒一次、只建一次评审。

`confirmGithub` 在回源前按 kind 把关，且**不**复用 `selfPr`：

```ts
if (kind === 'github.pr.opened' && this.deps.selfReview?.() !== true) { /* ignored/self-pr-disabled */ }
if (kind === 'github.pr.repo' && this.deps.repoReview?.() !== true) { /* ignored/repo-pr-disabled */ }
```

两个开关都关闭时，连 `gh` 调用都不发生。

### 4. 评审关系闸（`src/host/review/service.ts`）

`prepare()` 现在只认 `relation === 'reviewer'`，自提 PR 由 `selfReviewAllowed` 放行。新增一类放行：
**信号 kind 是 `github.pr.repo` 且 `review.repoPr` 打开时，允许 `relation === 'none'`**。
建议把端口改成更中性的形状，例如：

```ts
// 这条信号是否属于「作者可以不是评审人」的 PR：自提 PR 或仓库自有 PR。
ownPrAllowed?(signalId: string | undefined): boolean;
```

`core.ts` 里按信号的 kind 判断：

```ts
// github.pr.opened → review.selfPr
// github.pr.repo   → review.repoPr
```

失败理由 `not-reviewer` 的文案需要区分：现在的「你已不是这个 CR 的评审人」对 `relation === 'none'` 并不准确，
建议改为「这个 PR 没有请求你评审」，或在 `repoPr` 打开时不再走到这条失败。

### 5. 自动开始

`review.auto` 打开时，确认后的 `github.pr.repo` 直接排队准备评审；`maxConcurrent`、超时、失败重试、审计都复用现有逻辑。

### 6. 可选：能力声明

可在 `protocol.features` 里加 `github-repo-pr`，让插件面板能提示「核心还不支持仓库自有 PR」。不加也能工作：
旧核心会把 `github.pr.repo` 记成 `ignored/unverified-external`，只是排障时看不出原因。

## 验收标准

1. `review.repoPr` 默认关闭；关闭时 `github.pr.repo` 被结算为 `ignored`，不产生通知、不建评审、不调 `gh`。
2. 打开后，`bob` 在 `alice/private-project` 开的 open PR（未请求评审、未 @ alice）会收到「需要你评审」提醒，卡片可「开始评审」。
3. 同一 PR 同时被 `review-requested:@me` 与 `prScope: owned` 上报时，只提醒一次、只建一次评审（判重键 `ps:<sha>`）。
4. 别人在只读仓库（我没有 `admin`/`maintain`/`push`）开的 PR 判 `unrelated`，不提醒。
5. 作者是主人自己的 `github.pr.repo` 判 `unrelated`，不影响 `github.pr.opened` 的自提路径。
6. 已关闭/已合入的 PR 判 `superseded`；`head.sha` 非法判 `mismatch`；回源失败按 `verify-failed` 结算并可重试。
7. `review.auto` 打开时自动开始评审并遵守 `maxConcurrent`；关系闸放行 `relation = 'none'`，不再以 `not-reviewer` 终结。
8. 单测覆盖：kind 形状与 subject 解析、作者矩阵、权限矩阵、两个开关矩阵、与 review-requested 的判重。
9. 设置页开关可见、可保存、重启后保留；面板文案说明「仍需点卡片或打开全自动」。

## 对插件的影响

插件侧已经就绪，核心落地后无需改协议：

- `prScope` 默认 `review`，行为不变；打开 `owned` 才会上报 `github.pr.repo`。
- 事件键 `repo:<repo>#<n>:<headSha>` 与自提 PR 的 `self:`、待评审的 `review:` 互不冲突。
- 插件在面板里提示「需要核心同时打开 review.repoPr」，避免主人误以为插件没生效。
