## 主要变更

- **首个正式版**：`0.1.0` 与 `0.1.0-stage.0` 代码完全一致，只把版本号转正；npm 的 `latest` 从本版起指向正式版，预发布继续留在 `stage` 通道。
- **三路信号**：待评审 PR（`review-requested:@me`）、维护仓库的新 Issue、@ 提醒（Notifications，缺 `notifications` scope 时自动降级 search），分别翻译成 `my-superagent/v1` 信号交给超级助理。
- **未接入核心也能用**：没有 `dsh-my-superagent` 时照常轮询，新消息在右下角弹卡片（最多 4 张、12 秒消失、可点开 GitHub）；每条只弹一次，接入核心后同一事实仍会重新上报。
- **轮询节奏**：默认 5 分钟，可配 1 分钟～24 小时；实际间隔取配置与 GitHub `X-Poll-Interval` 的较大者，失败指数退避（最长 30 分钟），限流时等到 `X-RateLimit-Reset`。
- **配置页**：登录状态、核心能力、仓库与周期（共用一个保存按钮）、三路统计与核心信号；四张卡片可折叠，默认收起运行统计。
- **只读边界**：只用 `gh api` 的 GET / search / notifications，不评审、不评论、不写回，不读取也不记录任何 token。
- **内部**：npm 发布走 Trusted Publishing（OIDC）+ `--provenance`；release 流水线 gate/release 两段式，门禁不持有可写 token。

## 安装

```bash
# 正式版（npm）
dsh plugin --profile web add dsh-github-message@0.1.0

# 同一版本的 GitHub Release 附件
dsh plugin --profile web add https://github.com/xbzbing/dsh-github-message/releases/download/v0.1.0/dsh-github-message-0.1.0.tgz
```

装好后到 **设置 → 插件 → GitHub 消息** 确认 `gh` 已登录，再把要盯的仓库填进「维护仓库」；来源默认关闭，需要在超级助理的「来源」页打开 `github-message`。

## English

- **First stable release**: `0.1.0` is identical to `0.1.0-stage.0` — only the version string changed. From now on npm's `latest` points at a stable build, while pre-releases stay on the `stage` channel.
- **Three signal streams**: review requests (`review-requested:@me`), new issues in watched repositories, and @mentions (Notifications, falling back to search without the `notifications` scope), each translated into a `my-superagent/v1` signal for Superagent.
- **Useful without the core**: with no `dsh-my-superagent` installed the plugin keeps polling and pops new messages in the bottom-right corner (at most 4 cards, 12 seconds, click through to GitHub); each fact is shown once and is still reported after the core is connected.
- **Polling cadence**: 5 minutes by default, configurable from 1 minute to 24 hours; the effective delay is the larger of the configured interval and GitHub `X-Poll-Interval`, with exponential backoff (up to 30 minutes) on failures and a wait until `X-RateLimit-Reset` when rate limited.
- **Settings page**: login state, core capability, watch list and interval (one shared save button), per-stream stats and core signals; all four cards collapse, with run stats collapsed by default.
- **Read-only boundary**: only `gh api` GET / search / notifications — no review, no comment, no write-back, and no token is ever read or logged.
- **Internal**: npm publishing uses Trusted Publishing (OIDC) with `--provenance`; the release pipeline splits gate and release so the gate holds no writable token.

## Install

```bash
# Stable (npm)
dsh plugin --profile web add dsh-github-message@0.1.0

# The same version as a GitHub Release asset
dsh plugin --profile web add https://github.com/xbzbing/dsh-github-message/releases/download/v0.1.0/dsh-github-message-0.1.0.tgz
```

After installing, open **Settings → Plugins → GitHub Messages**, make sure `gh` is signed in, then fill in the repositories to watch. The source is off by default; enable `github-message` on Superagent's Sources page.
